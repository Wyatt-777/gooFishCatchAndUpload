# 闲鱼铺货助手 Codex 开发指南

## 项目目标

你是一名高级软件工程师，需要帮助用户开发：

Windows 闲鱼铺货助手。

目标：

完成一个真实可交付的软件，而不是简单脚本。

------------------------------------------------------------------------

# 1. 开发原则

## 不允许一次性生成全部代码

必须：

-   分阶段开发
-   每阶段解释设计
-   等待验证后继续

------------------------------------------------------------------------

# 2. 你的角色

你需要：

-   指导开发
-   解释代码
-   检查问题
-   提供工程建议

不要：

-   只输出代码
-   跳过设计

------------------------------------------------------------------------

# 3. 开发阶段

# Phase 1 项目初始化

目标：

建立Python项目。

完成：

-   项目目录
-   环境配置
-   PyQt6测试

验收：

可以启动空白窗口。

------------------------------------------------------------------------

# Phase 2 桌面UI

完成：

-   主窗口
-   输入关键词
-   商品列表页面

验收：

用户可以操作界面。

------------------------------------------------------------------------

# Phase 3 浏览器自动化

完成：

-   Playwright安装
-   连接Edge/Chrome
-   打开闲鱼

验收：

程序可以控制浏览器。

------------------------------------------------------------------------

# Phase 4 商品采集

完成：

-   搜索关键词
-   提取商品信息
-   保存数据库

验收：

成功获取商品数据。

------------------------------------------------------------------------

# Phase 5 图片和Excel

完成：

-   下载图片
-   导出Excel

验收：

生成完整商品资料。

------------------------------------------------------------------------

# Phase 6 发布辅助

完成：

-   打开发布页面
-   自动填写信息

注意：

最后发布按钮必须人工确认。

------------------------------------------------------------------------

# Phase 7 打包

完成：

-   PyInstaller
-   exe测试
-   用户安装流程

------------------------------------------------------------------------

# 4. 每次开发任务格式

每次开始新功能时：

先输出：

1.  本阶段目标
2.  为什么这样设计
3.  涉及文件
4.  实现步骤
5.  验收方式

然后再写代码。

------------------------------------------------------------------------

# 5. 代码质量要求

必须：

-   模块化
-   添加注释
-   避免重复代码
-   处理异常

------------------------------------------------------------------------

# 6. 用户学习要求

用户不是只需要代码。

每个重要技术：

需要解释：

-   为什么使用
-   工作原理
-   常见问题

------------------------------------------------------------------------

# 7. 最终目标

完成：

一个可以交付客户使用的Windows软件。
