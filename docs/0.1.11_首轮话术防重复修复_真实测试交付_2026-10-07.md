# 0.1.11 首轮话术防重复修复

## 本次依据

依据 2026-10-07 16:12 导出的真实质检包。包内有 27 个任务把完整目录作为新的顾客输入，又生成包含首轮话术的回复，其中 26 个提交后出现新的目录消息。旧版的 `dom_author_structure` 角色判断、缺少买卖双方身份绑定，以及发送结果长期不确定，共同形成重复路径。没有把所有未确认发送都认定为重复；截图中的昵称无法与匿名化会话唯一对应。

## 已实施

1. 批量读取、单条读取、媒体查找和发送回读共用角色解析。联合判断平台方向、发送者身份、平台自身消息标记及头像正文位置。旧的嵌套结构选择器仅作为诊断，不单独判定顾客。强证据冲突或缺失时使用独立的 `unknown` 角色。
2. 不确定消息保留质检原文、原方向及判断证据，不能建立新的顾客问题；最新消息角色不确定时跳过该会话，其他会话继续。待核验提交的匹配消息仅作为提交候选，不伪造成功发送或人工归属。
3. 首轮拦截独立检查当前和历史模板、完整多型号目录、本地提交占位、商家历史及订单状态。角色不确定的完整目录也会阻止首轮，不因无法证明发送成功而再次提交。
4. 顾客引用目录并提出独立问题时，保留顾客角色，提取独立问题回答。顾客明确要求重发目录时作为普通目录答复，不重置首轮资格。
5. 使用商家账号 ID 与平台顾客 ID 形成永久联系人，会话作为别名。别名升级保留关闭、占位及待核对状态；不按昵称或商品合并身份。稳定身份及平台新会话证据均完整时才允许自动首轮。重启、换商品会话、修改模板、清理质检内容不释放首轮事实。
6. 首轮占位和身份迁移使用 SQLite 事务。发送前再次核对身份、订单、消息角色、商家历史和目录证据。身份冲突取消提交，缺少身份重新确认取消首轮提交。
7. 发送核验需要唯一新增商家平台消息、精确正文、提交前基线及连续两次稳定读取；核对会话、商品和买卖双方身份。未确认结果保留占位，只读核对，不重复点击。
8. 升级迁移保留原始聊天、发送、价格及话术。历史商家活动、订单和疑似目录补齐首轮关闭或待核对状态；迁移有版本标记，不在每次启动重新扫描。质检导出升级为 schema 4，增加原始方向、角色来源、可信度及判断证据。

现有界面布局、客服设置框和接待操作沿用。没有新增模型或数据库服务。

## 保守处理的实际影响

当前已提供的质检资料不能证明真实页面一定包含完整的账号 ID、顾客 ID 和首次会话标记。新版仅采纳平台明确的首次消息标记，不把“当前看不到商家历史”当作首次接待证据，也不为了证明新顾客无限滚动聊天。

如果这些证据缺失，自动首轮可能不会发送；可信顾客的正常问题仍走普通回复。角色不确定时该会话不自动回复，轮询诊断显示“消息角色待核对”。需要真实测试检查角色识别准确性及平台身份字段的实际可用性。
