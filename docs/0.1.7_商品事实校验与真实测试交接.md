# 0.1.7 商品事实校验与真实测试交接

## 本次确认与备份

2026-10-05 经营者确认：现有三个铁塔型号的尺寸单位为厘米，质保三年，循环次数约100次。保留原来的价格、底价、平台绑定、聊天、人工锁和经营限制。

修改前备份在 `output/backups/before-fact-guard-20261005/`，含源码 ZIP 和 SQLite 一致性快照。已有数据库首次升级还会生成数据目录下的 `backups/before-0.1.7.db`。

## 回复链路变化

1. 当前顾客明确型号优先于近期顾客型号，再查平台绑定/标题。无法确定、同型号多版本或当前型号不在资料中，不套用另一款商品。
2. 商品原文解析并保存为结构化证据：电池类型、标称与实测容量、尺寸及单位、健康度、续航及条件、循环次数、充电时长、质保、成色/来源、库存备注、发货/售后和选装说明。未知属性保留未知。
3. 单独询问关键属性时，优先按当前商品资料简短直答。涉及实时适配、资料冲突、未知寿命等内容转人工。
4. 顾客纠正时取消待发追问，重新核查资料。聊天中的顾客断言及以前的商家回复都不能成为商品事实；旧问答只有通过当前事实检查才进入提示词。
5. LLM 输出、追加引导后的成稿以及发送前文本统一经过事实校验；人工在应用内编辑草稿也要校验。允许“不是铅酸，是磷酸铁锂”，区分明确的原车电池描述和出售商品，拦截否定对象不清的“不是 铅酸的”。
6. 数值按属性和单位核对，防止把健康度97当成97Ah容量、把标称30Ah当成实测30Ah、把充电时长当寿命。估计值和续航条件不能改成保证。
7. 首次目录按当前商品资料渲染，修复旧模板按三行切分四行商品段落的问题。保存自定义话术时校验；不合格的旧首轮话术保留原文，运行时使用当前目录。不合格追问不发送。
8. 资料版本包含所有商品字段、别名、平台绑定和固定话术。生成与发送之间改变资料会废弃旧草稿；旧版本待发追问取消。版本持久化，重启后仍检查。
9. 发送价格包含当前商品标价、明确的蓝牙选装计算和已记录的该商品议价结果。人工编辑不能凭空加入价格；金额按当前型号核对。

不改变页面布局或接待操作。资料不足/冲突只隔离相关会话；数据库或发送记录故障仍遵守现有全局安全暂停规则。

## 数据迁移及自定义追问

采用增量迁移，不提升全量目录重装标记，不重置人工价格。现有三个型号的无单位尺寸追加 `cm`，旧的一年质保同步为经营者已确认的三年，缺少循环次数时追加“约100次”。不同的人工自定义冲突保留供核实。

已识别的旧追问中“全国包邮发货，除了新疆、西藏”同步为“默认包邮，新疆、内蒙古、西藏不包邮，海南不发货”。其他文案保留，原追问另外保存为设置 `price_silence_follow_up_before_fact_sync_20261005`，数据库备份也包含原文。其他无法明确识别的冲突话术不自动改写。

新增表 `cs_product_fact_snapshots` 保存商品事实和证据版本，`cs_fact_generation_versions` 保存草稿/追问生成版本。原有质检决策和事件增加匹配来源、事实证据、版本、回复来源、校验结果、纠正/废弃/拦截原因；质检 ZIP 的 runtime.json 包含校验器版本。
