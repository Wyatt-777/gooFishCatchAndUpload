## 二、今天完成的工作

### 1. 修正采集数据来源

此前程序只解析搜索结果卡片，导致以下问题：

- 搜索卡片的标题可能其实是详情文案摘要；
- 搜索卡片价格可能是活动价、参考价或不完整价格；
- 详情页独立显示的属性规格没有被保存。

现已改为：

1. 搜索页只用于发现商品链接；
2. 逐条打开商品详情页；
3. 从详情页读取售价、完整“宝贝描述”、详情图片和属性规格；
4. 全部详情读取成功后才将任务标记为完成并保存。

## 四、已知限制与未解决项

1. **品牌并非总能自动填入。**
   闲鱼发布页给出的品牌选项受分类限制；若采集值不在选项中，必须人工选择或保留为空。当前策略是安全优先，不做近似匹配。

2. **区间价必须人工定价。**
   这属于商品本身多规格价格表达，不能自动转换为某一个发布价格。

3. **分类仍需用户确认。**
   这是既定安全边界，避免错误发布到不匹配类目。

4. **动态网页选择器存在维护成本。**
   闲鱼页面类名虽按语义前缀匹配，但若页面大改，可能需要更新 `xianyu_detail_parser.py` 或 `xianyu_publisher.py`。

5. **发布流程的 UI 端到端点击尚可再补一次。**

## 1. 项目定位

这是一个 Windows 桌面端的闲鱼铺货与客服辅助工具，当前包含两条业务链：

1. 卖家主页商品采集、图片下载、商品信息本地保存，以及发布页预填辅助；

当前客服链路仍是“人工审核草稿”模式，程序不会自动发送闲鱼消息。

## 7. Sol 下一阶段建议

### 7.1 先处理清洗结果，不要直接覆盖原始库

Sol 清洗后的文件建议另存为新文件，例如：

### 7.2 清洗重点

建议优先处理：

1. 同一商品的标题、别名和型号归并；
2. 将聊天中的事实拆分为价格、库存、规格、发货、售后和待确认信息；

4. 提取更贴近当前商家口吻的问答样例；
5. 删除订单状态、系统通知和无商品事实的噪声；
6. 对不确定事实标记为“需人工确认”，不要写入确定商品知识。

### 7.3 接回项目时的安全边界

- 清洗模型不能直接获得或输出 API Key；
- 模型生成内容不能直接变成商品事实，必须保留事实来源和人工确认状态；
- 不要开启自动发送；
- 先用人工审核草稿模式验证商品匹配、价格和口吻；
- 重新导入后至少验证：商品 ID 匹配、最低价为空时不会自动报价、无商品事实时会转人工。
