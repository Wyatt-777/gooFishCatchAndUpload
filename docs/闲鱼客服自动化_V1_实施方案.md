# 闲鱼客服自动化 V1 实施方案

状态：需求已确认，待分阶段实施
日期：2026-09-09
目标执行模型：Luna
基线项目：Windows / Python 3.12 / PyQt6 / Playwright / 本机 CDP / SQLite

## 1. 项目目标

在现有“闲鱼铺货助手”中增加独立的“客服接待”功能。用户点击“开始接待”后，程序新建并长期保持一个专用闲鱼客服标签页，周期性检查新消息，结合当前商品资料、最近聊天上下文和历史商家话术调用 DeepSeek，生成回复并按全局模式执行：

- 自动模式：策略校验通过后自动发送。
- 人工模式：生成可编辑草稿，由用户确认后发送。

该功能只能控制应用自己创建的客服标签页，不得导航、复用或关闭用户已有的其他闲鱼标签页。

## 2. 已确认的产品边界

### 2.1 运行方式

- 仅在用户手动点击“开始接待”后运行，不随应用启动。
- 只支持当前专用浏览器配置文件里已登录的一个闲鱼账号。
- 新建一个应用专用客服标签页，并在整次接待会话中复用该页。
- 每 10 秒开始一轮轮询。
- 每轮最多检查/处理 10 个发生变化或未读的会话。
- 同一顾客的连续新消息采用 10 秒静默合并窗口；窗口内出现新消息时重新计时。
- 全局统一选择“自动发送”或“人工确认”，V1 不支持按顾客、会话单独覆盖。
- 全局模式在点击“开始接待”前选定，运行期间锁定；如需切换，先停止接待再重新开始。
- 点击“停止接待”后应尽快安全停止，不再创建新回复任务；不得强杀线程或关闭浏览器进程。

### 2.2 输入与输出

需要理解的顾客输入：

- 文本：直接读取。
- 图片：从应用专用客服页取得图片或对消息节点截图，交给 DeepSeek 视觉模型理解。
- 语音：优先点击闲鱼页面自带的“转文字”并读取转写结果。

V1 回复输出：

- 默认发送文本。
- 在特定场景可额外发送一张本地图片。
- 可发送图片必须事先在配置页登记，并绑定商品和使用场景；模型只能返回已登记资源的 ID。
- 禁止模型生成图片，禁止读取或发送未登记的本地文件。
- 不生成或发送语音。

本地 Whisper 只保留为后续方案，V1 不安装、不打包、不调用。

### 2.3 知识与模型

- 文本和图片理解均使用 DeepSeek 官方 API；API Key 在桌面端配置。
- 文本模型、视觉模型和 Base URL 做成可配置项，避免把实验模型名固化到业务逻辑。
- 回复优先级必须是：硬性策略 > 商品知识库 > 当前实时对话 > 历史商家话术 > 模型常识。
- 商品事实由用户维护的本地知识库提供。历史聊天只用于检索相似问答和模仿商家表达方式，不能作为价格、库存、规格、发货等事实来源。
- 商品知识配置至少包括：商品名称、别名、平台商品 ID（可空）、标价、最低可接受价、规格、库存说明、发货说明、售后说明、补充知识、启用状态。
- 若未配置最低价，模型只能使用不承诺具体让价的礼貌话术。
- 任何报价都必须在本地策略层验证，不能只依赖提示词。

### 2.4 转人工规则

以下情况不自动发送，创建转人工事件并在本地电脑弹窗：

- 无法可靠识别当前会话关联的商品。
- 问题要求确定的商品事实，但知识库没有该事实或存在冲突。
- 退款、投诉、争议、威胁、平台申诉。
- 支付、账号或交易状态异常。
- 同一问题连续两轮回复仍未解决。

以下情况本身不触发转人工：

- 检索或模型置信度不足：应提出澄清问题或作保守回复。
- 议价：由模型处理，但受本地最低价策略约束。
- 顾客发送图片：交给 DeepSeek 视觉模型。
- 顾客发送语音：优先使用页面“转文字”。若页面无法转写，礼貌请顾客补充文字，不立即转人工。

本地弹窗应来自 Qt 主线程，并对同一事件去重。V1 不接入飞书或其他外部通知。

### 2.5 强制安全保护

- 每一批顾客新消息最多发送 1 条文本和 1 张已登记图片。
- 只有“最后一条未处理消息来自顾客”时才允许生成回复。
- 发送前重新读取当前会话；若出现更新消息，旧草稿标记为 `superseded`，重新进入 10 秒合并窗口。
- 相同入站批次指纹不得重复回复。内容审计记录清理后，去重指纹仍保留。
- 检测到验证码、登录失效、风控页、页面结构异常，立即停止整次接待并弹窗。
- 连续 3 次发送失败，立即停止整次接待并弹窗。
- 连续 3 次模型调用失败时停止自动发送并弹窗；已生成的人工草稿仍可查看，但发送前仍须重新校验页面状态。
- 所有 Playwright 操作必须有超时；重试必须有上限和退避，禁止无限刷新或无限重试。
- 不调用逆向得到的闲鱼内部接口来绕过页面，读取和发送均通过登录后的浏览器页面完成。

## 3. 明确不在 V1 范围内

- 多账号并行、多浏览器配置文件并行。
- 无人触发的开机自启或定时自动接待。
- 飞书、短信、邮件等远程通知。
- 本地 Whisper 语音转写。
- 发送语音、视频、文件或模型生成图片。
- 自动处理退款、投诉、支付、账号和平台申诉。
- 自动修改商品价格、库存、订单或交易状态。
- 云端向量数据库、模型微调、自动把模型回复反哺为训练数据。
- 接管用户已有闲鱼标签页或保存闲鱼账号密码/Cookie 到应用数据库。

## 6. 总体架构

```text
CustomerServicePanel（Qt 主线程）
  │ start/stop、全局模式、审核指令、配置维护
  ▼
CustomerServiceWorker（单个长生命周期 QThread）
  │ 同一线程内创建 BrowserManager 并持有专用 Page
  ▼
XianyuChatAdapter（所有闲鱼 DOM 细节集中在此）
  │ 会话摘要 / 消息 / 商品卡 / 图片 / 语音转文字 / 发送与回读校验
  ▼
ReceptionOrchestrator
  ├─ Debounce + Dedup + State Machine
  ├─ ProductMatcher + ProductKnowledgeRepository
  ├─ HistoricalExampleRetriever
  ├─ PrivacyRedactor
  ├─ DeepSeekClient（文本或视觉）
  ├─ ReplyPolicy（转人工、最低价、媒体白名单）
  └─ CustomerServiceRepository（审计、草稿、指纹、清理）
```

### 6.1 线程边界

- Qt UI 线程只更新界面、维护配置、展示草稿和发出命令。
- 所有 Playwright 对象必须在 `CustomerServiceWorker.run()` 所在线程创建、使用和销毁。
- Worker 使用线程安全命令队列接收 `approve/edit/send/dismiss/stop`，UI 不得跨线程直接调用 Page。
- 停止采用 `threading.Event`/条件变量唤醒，10 秒等待必须可中断；禁止 `QThread.terminate()`。
- Worker 退出时仅 `BrowserManager.disconnect()`，不关闭 Chrome/Edge 进程。

### 6.2 浏览器适配层

建议接口：

```python
class XianyuChatAdapter(Protocol):
    def open_dedicated_chat_page(self) -> None: ...
    def check_page_health(self) -> PageHealth: ...
    def list_changed_conversations(self, limit: int) -> list[ConversationSummary]: ...
    def open_conversation(self, conversation_key: str) -> None: ...
    def read_conversation(self) -> ConversationSnapshot: ...
    def request_voice_transcript(self, message_key: str) -> str | None: ...
    def capture_incoming_image(self, message_key: str) -> ImagePayload: ...
    def send_text(self, text: str) -> SendReceipt: ...
    def send_approved_image(self, path: Path) -> SendReceipt: ...
    def verify_outgoing(self, receipt: SendReceipt) -> bool: ...
```

实施规则：

- 闲鱼客服真实 URL、会话列表结构和选择器必须通过已登录测试账号的只读勘察确认，不能凭空猜测。
- URL、选择器、页面状态识别和 DOM 解析只放在 `customer_service/browser_adapter.py`。
- 优先稳定的 `data-*`、ARIA role/name 和明确文本；CSS class 只能作为有诊断信息的候补；避免绝对 XPath。
- 会话 ID、消息 ID 可从 DOM 获得时优先使用；否则使用规范化文本、方向、媒体摘要、DOM 签名组成稳定哈希。
- 适配失败时保存经过脱敏的 DOM 摘要和截图到现有调试目录，不在普通日志打印聊天正文或 API Key。
- 图片 URL 若需要登录 Cookie，不把该 URL直接交给云端；由 Playwright 获取或对消息节点截图，再以内存/base64 形式提交视觉模型。
- 顾客原始图片不长期保存。模型调用结束后删除临时文件；审计中只保留哈希和脱敏后的图片描述。

## 7. 轮询与状态机

### 7.1 接待会话状态

```text
STOPPED -> STARTING -> RUNNING -> STOPPING -> STOPPED
                    \-> HALTED（验证码/登录/页面/连续失败）
HALTED 只能由用户排障后再次点击“开始接待”恢复
```

### 7.2 单次回复任务状态

```text
OBSERVED
  -> DEBOUNCING
  -> READY
  -> READING_CONTEXT
  -> GENERATING
  -> POLICY_CHECK
       -> AWAITING_REVIEW -> SENDING -> SENT
       -> SENDING -> SENT
       -> HANDOFF
       -> SUPERSEDED（发送前发现新消息）
       -> FAILED
```

必须把合法迁移写成独立函数并单元测试，不允许 UI 直接拼接状态。

### 7.3 每轮算法

1. 检查停止信号和页面健康状态。
2. 从会话列表按“未读/发生变化优先、最久未处理优先”选最多 10 个，避免固定前 10 个导致饥饿。
3. 进入会话并读取当前快照；只登记新入站消息，不因旧消息重复生成任务。
4. 计算入站批次指纹，若已在永久去重表中则跳过。
5. 若距最后一条新入站消息不足 10 秒，更新 `debounce_due_at` 后继续扫描其他会话。
6. 到期后重新读取并冻结本批上下文，执行商品匹配、历史检索、脱敏和模型生成。
7. 执行本地策略校验。人工模式进入草稿队列；自动模式进入发送前检查。
8. 发送前再次读取快照。若入站批次变化，旧任务置为 `SUPERSEDED`，新批次重新等待 10 秒。
9. 最多发送一条文本和一张获批图片，随后回读确认出站内容存在，再写 `SENT` 和永久去重指纹。
10. 使用可中断等待直到下一轮 10 秒边界；命令队列到来时立即唤醒。

轮询间隔、每轮上限和合并窗口放入 `CustomerServiceConfig`，默认值固定为 `10 / 10 / 10`，V1 UI 可只读显示，不必开放任意调大。

## 8. 商品匹配和知识库

### 8.1 匹配顺序

1. 聊天页商品卡片的稳定平台商品 ID 精确匹配。
2. 商品链接中稳定 ID 精确匹配。
3. 规范化标题/用户维护别名的唯一精确匹配。
4. 只允许将模糊匹配作为候选提示；存在多个候选或没有可靠命中时转人工，禁止模型自行猜商品。

可允许用户从现有采集商品复制基础标题、描述、价格和图片到客服知识条目，但最低价、库存、发货和售后信息必须显式维护。

### 8.2 本地图片资源

每项资源至少保存：资源 ID、关联商品（可为通用）、显示名称、场景标签、给模型看的文字描述、绝对路径、SHA-256、MIME、启用状态。

发送前必须验证：

- 资源 ID 存在且已启用。
- 路径解析后仍是用户登记的同一个文件。
- 当前 SHA-256 与登记值一致；文件被替换时要求用户重新确认。
- 格式和大小满足页面上传限制。
- 资源关联商品与当前会话商品相符，或明确标记为通用。

## 9. 历史聊天导入和检索

### 9.1 导入

- 前端支持 ZIP、JSON、CSV。
- ZIP 只读取白名单后缀的普通文件，不解压到任意磁盘路径；限制压缩包大小、单文件展开大小和总展开大小，防止路径穿越与压缩炸弹。
- 自动识别当前样本的层级 JSON 与扁平 CSV 字段；提供导入预览、会话数、消息数、可生成样例数和错误数。
- 用源文件 SHA-256 和样例内容指纹保证重复导入幂等。
- 将连续的 `incoming` 合并为问题，将紧随其后的连续 `outgoing` 合并为商家回复。
- 只导入非空文本，不把无后续商家回复的轮次伪造成问答。
- 导入时先本地脱敏；原始 ZIP 不复制进应用数据目录。

### 9.2 可信度

- `imported_history`：用户导入的历史商家回复，可用于检索和风格参考。
- `human_confirmed`：用户在人工模式确认或编辑后由应用发送的回复，高可信。
- `auto_generated`：只进入 15 天审计，不进入检索样例库。

纯自动回复不得自动提升可信度或进入训练库，防止错误自我强化。

### 9.3 检索实现

样本约一千条，V1 不需要向量数据库。使用完全本地、可测试的轻量检索：

- 规范化全半角、大小写、空白和常见标点。
- 中文使用字符 2-gram/3-gram，英文和数字保留单词 token。
- 结合 token IDF、Jaccard/余弦相似度、关键词重合和可信度加权。
- 去除完全重复和高度近似的回复，返回 3–5 个样例。
- 用户消息和历史样例均视为不可信数据，不得把其中的“忽略规则”等文字当作系统指令。

历史样例在提示词中明确标记为“只模仿表达风格，不可当作商品事实”。

## 10. 隐私与 DeepSeek 编排

### 10.1 API 配置

前端提供：

- API Key（掩码输入，只支持覆盖/清除，不回显明文）。
- Base URL，默认 DeepSeek 官方地址。
- 文本模型名称。
- 视觉模型名称。
- 连接测试按钮（只发送固定测试文本，不发送顾客或历史数据）。

API Key 不得明文写入 SQLite、日志、调试文件或异常消息。Windows 交付优先使用 Windows Credential Manager（例如 `keyring` 后端）；若安全存储不可用，应阻止启用自动接待并给出明确错误，不得静默降级为明文。

DeepSeek 当前官方文档说明视觉输入需使用支持图片的视觉模型，并支持 base64、外部 URL 或 Files API。实现仍须以可配置模型名和能力检查为准，避免依赖实验模型永久存在：

- https://api-docs.deepseek.com/zh-cn/guides/vision/
- https://api-docs.deepseek.com/api/create-chat-completion/

### 10.2 本地脱敏

发送 API 前使用 `PrivacyRedactor` 处理当前上下文和检索样例，至少覆盖：

- 中国大陆手机号、座机号。
- 身份证、银行卡、邮箱。
- 订单号、快递单号和连续长数字。
- 明确的姓名/收件人字段。
- “地址/收货地址”等字段及其后内容。

替换为稳定占位符，例如 `[手机号_1]`、`[地址_1]`，保证同一请求内指代仍可理解。只发送当前问题所需的最少上下文，默认最近 20 条消息，并设置总字符/token 上限。

### 10.3 提示词上下文顺序

1. 固定系统策略和禁止事项。
2. 当前商品的结构化事实、最低价约束和可用图片资源清单。
3. 当前会话最近上下文和本批新消息（已脱敏）。
4. 3–5 条历史商家应答样例（已脱敏、仅供语气参考）。
5. 明确的 JSON 输出契约。

建议模型输出：

```json
{
  "reply_text": "",
  "media_asset_id": null,
  "intent": "product_question",
  "requires_handoff": false,
  "handoff_reason": null,
  "needs_clarification": false,
  "offered_price": null,
  "facts_used": []
}
```

解析失败可在不重复读取页面的情况下修复请求一次；第二次仍失败则记录模型失败，不发送未验证文本。

### 10.4 本地策略校验

模型输出必须经过纯本地 `ReplyPolicy`：

- 强制执行转人工意图。
- 校验商品身份和必需事实是否存在。
- 提取并校验所有价格；低于最低价时拒绝。可携带违反原因重试一次，仍不合规则使用不让价的安全话术，不因“议价”本身转人工。
- 校验 `media_asset_id` 白名单、商品关联和文件哈希。
- 限制消息数量和长度，去除空回复。
- 输出包含新手机号、地址、订单号等敏感数据时阻止发送。

低检索分数或模型低置信度不是转人工理由；应输出澄清问题或保守回复。但若问题要求确定事实而知识库缺失，则仍按“知识缺口”转人工。

## 11. 本地数据模型

建议继续使用现有 SQLite 文件，但把客服读写封装在独立的 `CustomerServiceRepository`，避免扩大现有 `SqliteRepository` 的职责。初始化采用 `CREATE TABLE IF NOT EXISTS` 和幂等索引，不破坏已有表。

建议表：

| 表 | 用途 | 保留策略 |
| --- | --- | --- |
| `cs_products` | 用户维护的商品客服知识和最低价 | 持久保留，用户删除 |
| `cs_product_aliases` | 商品别名 | 持久保留 |
| `cs_media_assets` | 获批本地图片及哈希 | 持久保留 |
| `cs_import_batches` | 导入哈希、计数和结果 | 持久保留 |
| `cs_training_examples` | 脱敏问答样例与可信度 | 持久保留，用户删除 |
| `cs_conversations` | 平台会话映射与当前状态 | 内容字段 15 天清理 |
| `cs_messages` | 读取到的入站/出站消息审计 | 15 天 |
| `cs_reply_jobs` | 检索、模型、策略、草稿和发送结果 | 15 天 |
| `cs_handoff_events` | 转人工原因、应用内通知和会话隔离状态 | 15 天 |
| `cs_run_sessions` | 每次开始/停止、计数和终止原因 | 15 天 |
| `cs_processed_fingerprints` | 防重复发送的不可逆哈希 | 持久保留，不保存正文 |

关键约束：

- `UNIQUE(conversation_key, platform_message_id)`（ID 存在时）。
- `UNIQUE(conversation_key, batch_fingerprint)` 防止重复任务。
- `UNIQUE(batch_fingerprint)` 或等价约束防止重复发送。
- 金额使用十进制定点字符串/整数分，不用浮点数。
- 审计时间保存带时区 ISO 8601；平台时间缺失时单独保存本地 `observed_at`，不得伪造平台时间。
- 正文与提示词只保留脱敏版本；API Key 永不入库。

### 11.1 15 天清理

- 应用启动时执行一次，此后每 6 小时最多执行一次。
- 删除 15 天前的消息正文、回复任务、转人工事件、运行会话和临时媒体。
- 清理使用小批量事务，失败只记脱敏错误，不影响接待主循环。
- 不清理商品知识、媒体资源配置、导入批次、可信历史样例和永久去重哈希。
- UI 提供“立即清理审计记录”按钮和最后清理结果。

## 12. UI 设计

在 `MainWindow` 新增顶层页签“客服接待”。建议布局：

### 12.1 顶部控制区

- 浏览器、登录、DeepSeek、商品知识库状态。
- 全局模式：`人工确认` / `自动发送`，默认首次安装选择人工确认。
- “开始接待”“停止接待”。
- 固定参数提示：10 秒轮询、每轮 10 会话、10 秒合并。

### 12.2 运行概览

- 当前状态、开始时间、下一轮时间。
- 本轮扫描数、等待合并数、待人工数、已发送数、转人工数、失败数。
- 最近一次页面/模型错误（脱敏）。

### 12.3 会话与草稿表

- 顾客显示名（可遮罩）、商品、最新消息摘要、状态、剩余合并时间、建议回复。
- 人工模式操作：查看上下文、编辑文本、选择/取消获批图片、发送、放弃、标记已人工处理。
- 发送按钮触发 Worker 命令；发送前仍执行页面重读和策略校验。

### 12.4 本地转人工弹窗

- 非阻塞弹窗/通知卡片，显示脱敏会话标识、商品、原因和“打开客服页”“查看草稿”。
- 验证码、登录失效或全局熔断使用更高优先级提示。
- 同一事件只弹一次，事件仍保留在列表直至用户处理。

### 12.5 客服配置

在“客服接待”内提供设置入口，至少含：

- DeepSeek 配置与连通性测试。
- 商品知识增删改查、启用/停用、从现有采集商品复制。
- 商品别名和最低价。
- 本地图片资源选择、预览、场景标签、哈希状态。
- 聊天记录 ZIP/JSON/CSV 导入、预览、结果和样例管理。
- 审计记录查看与立即清理。

## 14. 测试策略

### 14.1 单元测试

- JSON/CSV/ZIP 导入、CSV 嵌入换行、损坏文件、字段缺失、重复导入和 ZIP 安全限制。
- 连续方向消息切分后应得到预期问答样例。
- 手机、地址、证件、订单等脱敏；日志和模型请求均不含原值。
- 中文 n-gram 检索、去重、可信度排序，不把样例当事实。
- 商品 ID/别名唯一匹配和歧义转人工。
- 最低价边界、无最低价、金额格式、媒体白名单和转人工意图。
- 10 秒合并窗口重置、10 秒轮询、每轮 10 个、公平调度。
- 发送前新消息导致 `SUPERSEDED`。
- 同一指纹重复出现时不生成、不发送。
- 连续失败计数和熔断。
- 15 天边界清理与永久指纹保留。
- DeepSeek 超时、429、5xx、无效 JSON、视觉模型不支持图片、API Key 不出现在异常中。

### 14.2 浏览器适配测试

- 使用脱敏 HTML fixtures 和 fake Playwright Page 测试解析与选择器候补。
- 验证适配器只操作传入的专用 Page。
- 验证文本/图片发送后必须回读确认，单击动作不会因重试重复执行。
- 验证登录页、验证码、风控页、空列表和 DOM 变化都返回明确的 `PageHealth`。

### 14.3 集成与 UI 测试

- 用本地假 DeepSeek 服务测试完整生成流程，不把真实聊天发往测试网络。
- 使用可注入时钟，不让测试真实等待 10/10 秒。
- 人工草稿可编辑、发送、放弃；自动回复不进入样例库，人工确认回复进入。
- 启停按钮、模式切换锁定、退出应用时安全停止。

### 14.4 真实账号验收

只使用用户授权的测试账号和测试会话：

1. 点击开始后只新建一个专用客服页，不改动已有页面。
2. 11 个待处理会话时单轮最多处理 10 个，下一轮不饿死第 11 个。
3. 10 秒内连续发三条消息只生成一次回复。
4. 人工模式可编辑并发送，最终文本成为高可信样例。
5. 自动模式只在策略通过后发送，重复扫描不重复回复。
6. 生成期间收到新消息时废弃旧草稿。
7. 议价不低于最低价；缺少最低价时不承诺具体折扣。
8. 收到图片可由视觉模型理解；只发送登记且哈希未变化的本地图片。
9. 收到语音时尝试页面转文字；失败时请顾客补充文字。
10. 退款/投诉、商品无法识别、支付异常触发本地转人工弹窗。
11. 登录失效/验证码/页面异常立即熔断。
12. 人工停止后不再轮询或发送，浏览器进程和其他标签页保持不变。

## 15. 分阶段实施顺序

每阶段遵循现有《闲鱼铺货助手 Codex 开发指南》：先说明目标、设计、文件、步骤和验收，再编码；完成测试并向用户汇报后再进入下一阶段。

### Phase CS-0：基线与契约

- 检查未提交修改，运行现有测试和 Ruff。
- 建立本方案中的领域模型、配置默认值、状态迁移和抽象接口，不接浏览器、不调真实 API。
- 验收：旧功能测试不退化；状态机测试通过。

### Phase CS-1：数据库、导入、检索与隐私

- 实现客服表、15 天清理、永久去重哈希。
- 实现安全 ZIP/JSON/CSV 导入、样例切分、脱敏、幂等导入和本地检索。
- 用给定 ZIP 做只读导入验收，目标统计为 124 会话、5,317 消息、约 1,012 个可用轮次；差异必须解释，不能硬编码计数。
- 验收：导入、检索、脱敏、清理测试通过。

### Phase CS-2：配置 UI 与 DeepSeek 客户端

- 实现安全 API Key 存储、连接测试、模型配置。
- 实现商品知识、别名、最低价、本地图片资源和聊天导入配置页。
- 实现 DeepSeek 文本/视觉客户端、超时、退避、JSON 解析和错误脱敏。
- 验收：假服务测试通过，真实连接测试只由用户主动触发。

### Phase CS-3：闲鱼客服页只读适配

- 用真实已登录页面确认 URL、DOM 和稳定选择器。
- 只实现页面健康检查、会话列表、会话切换、消息读取、商品卡匹配、图片取得和语音转文字；禁止发送。
- 保存脱敏 fixtures 和诊断证据。
- 验收：连续运行至少 30 分钟只读轮询，无重复消息、无其他标签页影响。

### Phase CS-4：人工确认闭环

- 实现 Worker、可中断轮询、10 秒合并、每轮 10 个、公平调度。
- 接入知识、检索、脱敏、DeepSeek、策略检查和人工草稿队列。
- 实现由用户点击发送的文本，以及发送前重读、回读校验和去重；媒体字段保留接口，但本阶段不发送图片。
- 验收：人工模式文本闭环的真实账号用例通过。

### Phase CS-5：自动发送、转人工与熔断

- 开启全局自动模式。
- 实现全部转人工规则、最低价约束、重复保护、更新消息废稿和连续失败熔断。
- 转人工采用会话级隔离：持久保存程序内通知并跳过该顾客，主循环继续处理其它顾客；人工标记处理完成后，仅恢复该顾客后续新消息。外部通知渠道待选定后接入，不使用阻塞式弹窗。
- 纯自动回复只写 15 天审计，不进入训练样例。
- 验收：安全矩阵和真实账号自动模式测试通过。

### Phase CS-6：媒体、清理、打包与交付

- 完成顾客图片到视觉模型、页面语音转文字、人工/自动模式下的获批本地图片选择与发送。
- 完成启动/周期清理、应用退出、日志脱敏、PyInstaller hidden imports 和干净 Windows 打包验证。
- 更新 README、架构和用户说明。
- 验收：本方案 Definition of Done 全部满足。

## 16. Definition of Done

只有同时满足以下条件才能声明 V1 完成：

- 手动开始、专用客服页、单账号、10 秒/10 会话/10 秒合并均真实生效。
- 人工和自动两种全局模式均可用，发送前均有更新消息校验。
- 文本、顾客图片、页面语音转文字和获批本地图片流程可用。
- DeepSeek Key 安全存储，所有云端上下文经过本地脱敏和最小化。
- 历史聊天可重复导入且幂等，样例仅用于风格；自动回复不污染检索库。
- 商品事实和最低价由本地知识库控制，模型不能绕过。
- 所有转人工、去重、验证码/登录/页面/连续失败熔断规则通过测试。
- 审计内容在 15 天后自动清理，永久去重哈希保留。
- 现有采集、图片下载和发布预填功能无回归。
- `pytest`、`ruff check` 和 Windows 打包验收通过。
- README 明确说明平台页面变化、账号风控、云端模型隐私和人工监督边界。
