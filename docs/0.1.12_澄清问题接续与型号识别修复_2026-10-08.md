# 0.1.12 澄清问题接续与型号识别修复

本次按用户确认的方案实施，针对“能跑多远啊 → 询问型号 → 60V30 → 再次询问型号”的问题。源码修复和离线验收已完成，交付 0.1.12 安装包。真实闲鱼页面的收发、角色及 DOM 行为尚未验证，不能把离线验收表述为线上零回归保证。

## 修复结果

1. 商品匹配、语义分析和上下文使用统一型号语法。支持 `60V30`、`60v20`、`48V30`、`60伏30`、全角输入，并保持原有带单位及紧凑型号写法。日期、订单号、价格、功率、距离和较长数字不能被截取成已知型号；未知型号不能回退到历史商品。
2. 澄清问题随本轮决策保存，不增加数据库表或迁移。仅最近尚未解决、且对应一次已确认商家发送的型号澄清可以跨轮恢复；保存原问题、缺项、源消息键、正文指纹和商品/商家/顾客绑定。
3. 型号补充后，商品事实回答使用接续后的完整属性问题。截图流程会直接回答当前 6030 资料中的“二轮原装车、单人、平路、预估 50–60 公里”，不依赖模型猜测。尺寸、实测容量也通过同一路径。
4. 原始输入仍供价格、订单、数量和议价使用。新问题、纠正、订单操作、人工回复、未知角色或绑定变化会阻断旧问题接续；完成后的问题不会无限向前搜索并重新激活。
5. 生成和发送前均检查重复询问已提供的型号及是否回答接续属性。人工审核后会重新读取来源和商品资料；新消息、原问题变化或事实变更会拒绝旧草稿提交。
6. 型号中的电压和容量不再成为议价出价，包括议价模块自身的备用解析。`60V30便宜点` 不产生 30 元报价，`60V30 500行吗` 保留真实 500 元出价。`60V30两组` 能识别两组；数量总价和最低价权限沿用原有规则。
7. 质检导出增加问题来源和缺项信息，消息键、轮次键保持同一套匿名化映射；从可见历史接续的文本仍会先脱敏。

- **66 项新增回归用例全部通过。**使用临时 SQLite 数据库和离线页面替身，模拟的是现行提交许可与发送回读契约，没有连接真实浏览器、调用 LLM、发送客户消息或实际改价。
