# 顾客状态数据库实施说明

## 目标

在短期聊天记录和 Worker 内存之外，保存可跨重启恢复的长期顾客状态。聊天正文仍按原有 15 天策略清理，顾客主档和状态事件不随聊天正文删除。

## 身份规则

- 当前闲鱼页面稳定提供会话 ID，但不保证提供全局买家 ID。
- 有稳定 `platform_customer_id` 时，同一买家的多个会话可以链接到同一主档。
- 没有买家 ID 时，以会话 ID 建立独立主档。
- 禁止仅凭昵称合并顾客，避免同名串档。

## 数据表

- `cs_customers`：长期顾客主档，包括生命周期、意向等级、销售阶段、订单状态、商品与规格意向、预算/报价、跟进时间、人工接管状态和时间戳。
- `cs_customer_conversations`：顾客与一个或多个闲鱼会话的稳定映射。
- `cs_customer_state_events`：幂等、追加式状态事件，用于审计状态为何变化。

## 自动状态

生命周期包括：新顾客、已互动、已明确需求、议价中、准备下单、已下单、售后、流失。

程序只根据确定性证据更新状态：明确型号/续航/功率、明确报价、议价结果、下单/待付款表达、售后关键词、已验证发送结果和人工接管事件。自由生成的模型措辞不能直接修改顾客状态。

## 保留与迁移

- 初始化时自动把现有 `cs_conversations` 回填为长期顾客主档。
- 原有会话、消息、知识库和首轮目录记录不修改。
- 15 天审计清理不会删除三张长期顾客状态表。
- 正式数据库迁移前备份位于：
  `C:\Users\lenovo\AppData\Local\XianyuAssistant\backups\xianyu_assistant-before-customer-state-20260921.db`

## 当前限制

当前版本已经具备数据库、自动写入和查询接口，但尚未增加单独的“顾客管理”图形界面。后续可以基于 `list_customer_profiles`、`get_customer_profile` 和 `list_customer_state_events` 增加筛选、标签、备注和人工调整页面。
