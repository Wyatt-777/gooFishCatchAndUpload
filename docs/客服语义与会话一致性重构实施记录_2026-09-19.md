# 客服语义与会话一致性重构实施记录

日期：2026-09-19

## 修复目标

修复以下两类高风险问题：

1. 将型号、功率、续航、容量、尺寸等数字误识别为顾客报价；
2. 页面会话切换未完成时读取或发送，导致已读、上下文和回复对象错位。

## 已实施架构

客服主链路调整为：

```text
稳定会话身份确认
→ 完整顾客轮次归并
→ 结构化语义提取
→ 本地数字单位与议价资格裁决
→ 回复生成
→ 语义/数字/政策校验
→ 会话版本发送预留
→ 单次发送
→ 出站消息回读确认
```

### 结构化语义

新增 `semantic_analysis.py`。它会区分：

- 电池型号；
- 电压与容量；
- 电机功率；
- 续航要求；
- 数量；
- 金额；
- 询价、议价、比较、纠正和下单意图。

明确单位由本地程序确定。剩余无单位数字可交给模型输出严格 JSON，随后仍由本地规则复核。模型无法把已经绑定到 `km/W/V/Ah` 或电池型号的数字提升为金额。

### 议价准入

只有以下情况可以产生 `money_offer`：

- 数字带“元、块、¥/￥”；
- 同一句包含明确议价或改价表达；
- 会话已经处于议价状态，顾客继续回复无单位金额。

`我4824都能50Km` 和 `60伏20安，25公里的多少钱` 均不会进入议价状态。

### 完整顾客轮次

首次启动和重启后，不再只取连续顾客消息中的最后一句。最后一条商家消息之后的全部顾客消息作为一个完整轮次处理。默认静默归并窗口由 3 秒提高到 6 秒，新消息会废弃旧任务并重新归并。

### 会话身份确认

浏览器适配器不再在点击前写入“当前会话”。点击后必须连续两次读取到目标活动会话的稳定 ID 才确认切换。自动模式遇到 `dom-*` 临时会话 ID 时停止自动处理并转人工。

发送前同时核对：

- 目标会话 ID；
- 顾客消息批次指纹；
- 最后一条消息方向；
- 当前商品 ID；
- SQLite 中的会话版本；
- 永久去重指纹。

### 持久化审计

新增：

- `cs_conversation_states`：会话版本、最后观察/处理消息和人工所有权；
- `cs_customer_turns`：完整消息批次、语义 JSON、决策 JSON、最终回复和状态；
- `cs_send_outbox`：发送预留、预期会话版本、回复指纹和回读结果。

自动发送的最终回复文本会写入审计记录，不再只留下空草稿。

## 失败策略

- 语义模型超时或 JSON 无效：不推测价格，改为澄清；
- 顾客没有议价但模型生成“某数字不行”：本地拒绝并重试；
- 两次生成仍不合格：任务失败，不自动发送；
- 会话 ID、商品 ID 或版本不一致：旧任务作废；
- 点击发送后结果不确定：禁止自动重试；
- 无法取得稳定会话 ID：转人工。

## 回归覆盖

新增测试覆盖：

- `4824 + 50Km` 不得识别为 50 元；
- `60伏20安 + 25公里 + 多少钱` 不得识别为 25 元；
- 模型不能把 `350W` 提升为 350 元；
- 已有议价状态下的裸数字仍可正确继承；
- 首次启动保留完整连续消息；
- 页面活动会话没有切换时拒绝读取；
- 会话版本变化时发送预留失败；
- 已验证发送保留最终回复、处理游标和出站消息 ID。
