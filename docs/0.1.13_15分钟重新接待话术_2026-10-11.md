# 0.1.13：满15分钟后新问题再次发送接待话术

本版本依据经营者新增要求，保留首次接待规则，并允许同一顾客间隔15分钟后提出新问题时再次发送已配置的首轮话术，同时回答本次问题。

## 使用规则

| 情况 | 行为 |
| --- | --- |
| 符合原有首次接待条件的新顾客 | 发送已配置的首轮话术 |
| 距该顾客上次消息不足900秒，再次追问 | 正常回答，不重复话术；本次消息重新计时 |
| 间隔恰好900秒或更久，再询问新的问题 | 发送首轮话术，并回答本次问题 |
| 连发问题与补充型号，尚未发送回复 | 合并为同一轮资格，最多发送一次话术 |
| 仅回复“收到”“谢谢”“好的”、单独补充型号、重复上一问题 | 不因此重发接待话术 |
| 已有订单、人工接管或未关闭的转人工任务 | 保留原有接待限制，不重发营销话术 |
| 身份/消息角色不明、旧发送仍待核对或旧话术仍被占位 | 保留禁止发送的保护 |

计时基准为顾客消息到达时间，使用可信的完整平台时间；无完整日期和时区时使用程序首次观察到该消息的时间。不是从商家回复时间、话术发送时间或审核时间计算。满15分钟而顾客没有发来新问题时，不主动发送本条话术。

例如：10:00问价，10:10追问，10:20问尺寸，均属于连续接待；10:35再问续航时，可以再次发送接待话术。10:10和10:20的顾客消息都会重新计时。

同一商家和顾客在不同商品会话间共享计时；不同商家、不同顾客相互隔离，不按昵称合并。重启保留计时、消息去重和发送占位记录；反复读取相同消息不会刷新时间或重发。资格在新问题到达时确定，人工审核等待超过15分钟不会让原来不符合条件的草稿获得资格。

## 升级及保护

数据库仅新增计时、去重和接待资格表，保留旧首轮标记、订单锁及原有商品、报价、话术设置。旧版本没有留下可信计时记录的会话，需要先观察一次新顾客消息建立计时基准，后续满足15分钟间隔时生效；不会把加载的旧历史冒充新询问。

再次接待的资格必须绑定本轮稳定消息ID和商家/顾客身份，发送前原子占位。生成草稿、批准草稿和点击提交前继续复核，顾客新增消息、商家介入、身份改变或角色不明会阻止旧草稿提交。确认发送后关闭该轮资格；确认未提交才能释放占位。旧发送结果不确定或进程在占位后退出，不会因另一个15分钟间隔而解除旧锁。

默认多型号目录与单型号简短回答组合时，在回答前明确对应型号，防止目录最后一个型号影响事实校验；商品事实校验、价格校验和原有型号补全逻辑继续保留。人工审核仍须批准，自动模式沿用现有启动要求。

质检包新增脱敏的 `contact_activity.jsonl`、`contact_seen_messages.jsonl`、`recontact_windows.jsonl`，并记录 `recontact15-v1` 策略版本，可核对实际间隔、资格消息及占位结果。
