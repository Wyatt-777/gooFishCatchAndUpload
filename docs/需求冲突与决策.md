# 需求冲突与决策记录

本文在 V1 PRD、技术架构设计和 Codex 开发指南之间进行交叉核对。标记为“待确认”的条目不阻塞 Phase 1，但必须在对应开发阶段开始前定案。

| ID | 发现 | 影响 | 建议决策 | 状态 |
| --- | --- | --- | --- | --- |
| D-01 | PRD 要求“使用用户已有浏览器环境”，而 Playwright 通常不能直接接管一个已正常启动的 Chrome/Edge。 | 直接启动默认用户配置可能被浏览器锁定，也会影响用户日常浏览。 | **已确认：**用户自行以 CDP 远程调试端口启动 Chrome/Edge，应用通过 `127.0.0.1` 连接。Chrome 136+ 必须额外使用非默认 `--user-data-dir`。 | 已确认 |
| D-02 | PRD 表示“不保存账号信息”，又要求“保存浏览器状态”。浏览器状态通常包含会话 Cookie。 | 文案若不澄清，会造成隐私承诺和实现不一致。 | 应用数据库不保存用户名、密码或 Cookie；浏览器的 CDP 用户目录保存登录会话。首次运行时明确告知，并在后续设置中提供“清除浏览器会话”操作。 | 已确认 |
| D-03 | “本地验证、不依赖服务器”的简单激活码，不能同时提供可靠的防伪、防复制与撤销能力。 | 激活逻辑容易被复制或逆向，无法吊销泄露码。 | V1 定位为轻量离线授权：使用公钥签名的、可含设备指纹与到期日的许可证文件；若只需演示，可先实现可替换的本地验证接口。强防伪/撤销应进入服务端授权范围。 | 待确认 |
| D-04 | PRD 要求任务可“暂停”，架构的 Task Manager 只列出创建、暂停、恢复、完成，未定义中断时的数据一致性。 | 会出现重复采集、进度失真或无法恢复。 | **已确认：**状态机为 `waiting → running ↔ paused → completed / failed / cancelled`；按已写入商品去重，恢复时可安全重试。暂停在当前浏览器操作完成后生效。 | 已确认 |
| D-05 | PRD 的图片字段为单数 `image`，但目录设计、Product 结构和发布流程都需要多图。 | 数据表和导出字段无法准确表达多张图片。 | **已确认：**Product 使用一对多 `product_images` 表；Phase 5 将在该表回写本地路径，Excel 可导出多路径。 | 已确认 |
| D-06 | `category` 是采集和自动填写字段，但未定义其来源和平台映射。 | 页面变更后自动发布容易填写错误或失败。 | **已确认：**V1 保存采集到的原始分类文本；发布前由用户检查，暂不做自动分类映射。 | 已确认 |
| D-07 | 文档要求“真实可交付”，但 V1 也要求不做批量发布及最终人工确认。 | “辅助发布”边界需避免被实现成自动发布。 | 自动化只能打开发布页、预填信息并在提交前停止；禁止程序点击最终发布/确认按钮。 | 已统一 |
| D-08 | 采集和复制图片/描述可能涉及平台规则、隐私和知识产权，但需求未提出合规边界。 | 可能带来账号、版权与产品风险。 | 仅处理用户有权使用的公开信息；首版增加使用提示、速率限制、操作日志和人工确认。正式上线前复核平台规则。 | 待确认 |

## 本阶段采用的暂定边界

Phase 1 只搭建窗口和工程基础，不保存账号信息、不启动浏览器、不采集数据，因此不预先锁死 D-01 至 D-06 的实现方案。
