# 闲鱼铺货助手：用户操作与交付说明

## 1. 交付物

正式发布目录为：

```text
dist\XianyuAssistant\
```

必须整体复制该目录，不能只复制 `XianyuAssistant.exe`。目标电脑需要 Windows 10/11、Chrome 或 Edge，以及可正常访问闲鱼和模型服务的网络。

## 2. 首次启动

1. 双击 `XianyuAssistant.exe`；
2. 在“浏览器设置”选择 Chrome 或 Edge 并启动浏览器；
3. 在程序启动的浏览器资料目录中自行登录闲鱼；
4. 确认连接状态正常后再进行采集、发布辅助或客服同步；
5. 如需客服草稿，在“客服设置”填写 DeepSeek 配置。API Key 不会回显，并保存在 Windows 凭据存储中。

## 3. 安全边界

- 仅采集用户有权处理的卖家主页和当前登录账号数据；
- 发布辅助不会选择最终类目，也不会点击最终发布按钮；
- 区间价必须由用户填写单一发布价；
- 属性值只有完全匹配时才自动选择；
- 客服默认保持人工审核；自动发送只能由用户主动选择并在每次启动时再次确认；
- 历史聊天和清洗知识只作参考，当前价格、库存、安全、兼容性、物流及售后必须重新确认；
- API Key 不写入 SQLite、普通日志或知识库导出文件。

## 4. 清洗知识库导入

在“客服设置 → 清洗知识库导入”中：

1. 选择带有 `knowledge_base_version` 的项目知识库 JSON；
2. 检查预览中的商品、商品聊天、历史问答和错误数；
3. 点击“导入清洗知识库”；
4. 相同文件重复导入时不会重复写入；
5. 已有的非空人工商品事实、最低价和启用状态不会被清洗文件覆盖；
6. 知识文档保留来源会话 ID、来源消息 ID、质量标记和使用注意。

## 5. 本地数据、日志与清理

默认目录：

```text
%LOCALAPPDATA%\XianyuAssistant\
```

主要文件：

- `xianyu_assistant.db`：商品、任务、客服知识、草稿和审计数据；
- `xianyu_assistant.log`：不包含聊天正文和 API Key 的运行日志。

应用启动时会按六小时间隔检查过期数据。也可以在“客服设置”点击“立即清理过期审计记录”。该操作只删除超过 15 天保留期的会话内容、草稿、转交事件和运行会话，不删除商品知识、清洗知识文档、可信历史样例及永久去重指纹。

## 6. 发布前验证

开发电脑执行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\ruff.exe check src tests scripts
.\.venv\Scripts\python.exe -m compileall -q src scripts
.\scripts\build_windows.ps1
```

随后在一台没有 Python 开发环境的干净 Windows 电脑上验证：

1. 程序可启动且不会弹出缺失 DLL/模块错误；
2. Chrome/Edge 可以启动、连接并保持登录；
3. 可完成一条详情采集和图片下载；
4. 发布辅助能预填描述、图片、单一价格和精确匹配属性，且不会发布；
5. 客服设置可安全保存/清除凭据；
6. 聊天同步只读，知识库可预览并幂等导入；
7. 客服默认草稿等待人工审核；自动发送必须先显示二次确认，且安全、售后、争议和媒体回复转人工；
8. 数据目录和过期审计清理入口可用。

## 7. 故障排查

- 无法连接浏览器：确认浏览器由应用启动，或远程调试端口与设置一致；
- 页面读取失败：先确认登录状态、验证码、风控提示以及闲鱼页面是否改版；
- 区间价无法预填：在发布确认窗口填写一个明确价格；
- 品牌未自动选择：当前类目不存在完全一致选项时应人工处理；
- 模型测试失败：检查 Base URL、模型名称、网络和 Windows 凭据中的 API Key；
- 需要诊断：从“客服设置”打开本地数据目录，提供脱敏日志，不要发送数据库、Cookie 或 API Key。

## 人工审核发送

1. 在“客服接待”中启动接待，等待草稿进入“待人工审核”；
2. 选中草稿并检查内容，可直接编辑；“保存草稿编辑”只更新本地草稿；
3. 点击“确认并发送”才会向当前顾客发送编辑框中的文本；
4. 程序会在发送前重新读取会话。若顾客新增了消息，旧草稿会自动作废，不会发送；
5. 页面发送动作只执行一次，不会因超时自动重试；发送后必须回读到新增的相同出站文本才显示“已发送”。

## 全自动客服（回复与改价）

1. 默认运行模式仍为“人工审核草稿”；
2. 只有主动选择“全自动（回复与改价，启动时需确认）”，并在警告框确认真实消息和订单改价风险后才会启动；取消确认不会启动接待；
3. 自动回复与人工确认共用同一发送安全链路：发送前重读会话、拦截已处理指纹、只执行一次发送动作、发送后回读确认；
4. 顾客在生成后发来新消息时，旧回复会作废并基于新消息重新处理；
5. 投诉、退换、售后、安全风险、隐私风险、图片回复及策略不确定项不会自动发送，而是进入转人工状态；
6. 连续 3 次模型失败或发送失败时，接待会自动暂停；明确判定为“点击未生效”的回复会回到待人工审核，不会自动重试；
7. 顾客明确已拍下/待付款并要求按已接受价格改价时，程序会再次核对商品、最新顾客消息以及 `最低成交价 ≤ 最终价 ≤ 标价`，通过后先完成页面改价，再发送确认回复；
8. 自动改价的页面操作仍只执行一次；节点不唯一、金额回读不一致、确认按钮异常或结果不明确时禁止自动重试，该顾客转人工，其他顾客继续处理；
9. 多件订单的单价与总价需要人工核对，不进入自动改价；运行期间模式选择会锁定，停止后才可切换。

图片发送、语音发送和文件发送仍不开放。
