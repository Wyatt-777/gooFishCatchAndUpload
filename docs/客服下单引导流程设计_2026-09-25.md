# 客服下单引导流程设计

## 目标与边界

在保持现有闲鱼卖家短句、先答当前问题、不重复问型号的习惯下，帮助有明确购买意向的顾客完成型号确认、疑虑消除、价格确认和站内下单。销售引导只改变下一句的选择，不覆盖商品事实、议价、改价、安全和转人工规则。

本方案现已作为接待页中的“试用下单引导”选项实现。开关默认关闭，每次启动接待前选择；运行中锁定。关闭时沿用原有销售逻辑，开启时使用下述克制引导规则。人工审核模式可先检查草稿，全自动模式会直接发送通过现有校验的回复。

## 每轮处理顺序

1. 先识别顾客这一轮的问题，以及上下文里已确认的型号、用途、数量、蓝牙选择、收货地区和已接受价格。
2. 先回答当前问题。没有事实依据的容量、续航、适配、库存、发货时间或运费不作肯定承诺。
3. 判断是否有足够的购买意向。仅当顾客主动询问价格、适配、比较、优惠、购买方式，或明确表示想买时，才考虑推进一步。
4. 每轮最多追加一个动作：一个关键问题、一句与问题直接相关的已确认卖点，或一句下单操作提示。顾客只在确认“还有吗”“对吗”时，保持短答。
5. 顾客已拍、待付款、已付款，或出现售后、安全、投诉、物流异常时，停止销售引导，转入对应服务流程。

## 会话阶段

| 阶段 | 进入证据 | 本轮动作 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 接待 | 新咨询、简单确认 | 直接回答；无型号的泛询价使用已保存的话术 | 顾客给出型号、车型或用途 |
| 需求确认 | 问续航、容量、适配，但缺少决定答案的信息 | 只问一个最关键的缺口；已问过的不再问 | 能唯一确定型号和当前问题 |
| 方案说明 | 型号已确定，顾客继续比较或核实 | 只答所问；必要时补一条与顾虑直接相关的已确认事实 | 顾客询价、问优惠、表达购买意向 |
| 价格确认 | 顾客问价、议价或比较价格 | 使用当前商品标价及既有确定性议价结果，不主动透露底价 | 顾客接受价格或问如何购买 |
| 下单提示 | 唯一型号、数量和价格已明确，顾客问“怎么拍”或表示要买 | 简短说明在当前闲鱼商品链接拍下；有已接受改价时按既有改价流程处理 | 订单已拍下或进入待付款 |
| 订单服务 | 已拍、待付款、已付款或平台确认发货 | 处理改价、订单或售后事项；不继续催单 | 订单流程结束或人工接管 |

阶段不是按轮次强制推进。顾客直接问“怎么拍”时，可以跳过前面的销售话术，但下单前仍需确认影响订单的型号、数量和最终价格。

## 对话示例

下面的话术是表达方式示例。涉及价格、容量等数字时，以运行时当前商品资料为准。

| 顾客消息或上下文 | 建议回复 | 原因 |
| --- | --- | --- |
| “还有吗” | “有的” | 简短确认，不追问车型和续航 |
| “实价吗”，此前未确定型号 | 程序中保存的价格／型号话术 | 保持现有配置，不临时编造一个实价 |
| “标价多少”或“240元是哪一种”，指向低于该型号价格的页面活动价 | “页面标价对应低容量款，续航比较低” | 对全部现有型号按页面价与商品资料比较，不把低容量活动价当作标准型号报价；已报过的成交价、具体型号标价及议价仍按原路径处理 |
| “容量还有多少”，未确定型号 | “你要哪个型号” | 只问决定容量答案的一个信息 |
| 上一轮问容量、商家问型号后，顾客说“60 30” | “6030容量29安左右 健康度97以上” | 继承上一轮问题，把“60 30”识别为 6030 |
| 已确定 6030，顾客问“多少钱” | “6030 678元” | 只回答价格，不重复整段目录 |
| 只问价格，未问适配或续航 | 直接回答价格或既有话术 | 不主动附加“二轮还是三轮”的追问，也不安排这类沉默追问 |
| 已确定型号，顾客说“能装我就要” | “电池仓尺寸发我下 我帮你核” | 适配未核实前不承诺能装 |
| 顾客问“怎么拍”且型号、数量、价格已明确 | “在这个链接拍就行” | 给具体下一步，不再重复推销 |
| 已接受单件议价，顾客说“拍了，改价” | 走现有订单及改价核验流程 | 不重新还价，不直接凭聊天内容宣布已改价 |

## 主动追问

保留现有的“自动发送后、顾客沉默 30 分钟、9:00–22:00、每次最多一次、发送前回读”的技术约束，但缩小触发范围：

- 只有顾客明确表达购买或选择意向、且本轮确有一个待回答的关键问题时，才预约追问。仅发送目录、普通问价、售后或简单确认时不预约。
- 追问延续上一次问题，使用一个短句，如“电池仓尺寸方便发我下吗”，不重复目录、不另起推销话题。
- 顾客、人工商家或平台订单状态有任何新变化，立即取消；已经主动追问过一次就停止，不循环催促。

## 实现位置与验收

- 在 `customer_service/sales.py` 调整 `build_sales_plan`：先判断本轮是否适合推进，再按阶段选至多一个动作；目录回复不自动预约泛化追问。
- 在 `customer_service/customer_service_worker.py` 继续让销售建议排在事实回复、议价和本地策略之后；下单提示不得绕过发送前回读、订单改价和转人工校验。
- 使用现有 `SalesStage`、顾客状态与销售状态持久化。阶段推进只依赖顾客消息、当前商品资料和已验证的订单／发送事件，不依赖模型自由措辞。
- 回归场景至少覆盖：截图中的“实价吗 → 容量还有多少 → 60 30”；只问价格不被连续追问；已问过型号不重复问；议价接受后“怎么拍”不重新还价；人工接管、已拍和售后不催单；30 分钟追问在新消息到达后取消。

判断效果时同时看下单转化与干扰指标：重复追问、无关附加句、未核实承诺、错误报价和顾客明确拒绝后的继续追问。后五项应优先归零，避免为了转化破坏现有聊天习惯。
