# 0.1.6 核对暂停修复与防护说明

日期：2026-10-03。基于另一台电脑的 0.1.5 质检包、数据库、日志及暂停截图实施。

## 已修复的直接原因

过去的延后核对把会话定位、聊天读取、发送确认和数据库更新放入同一个异常处理。找不到会话时误报“发送核对记录无法保存”，暂停全局，并且没有推进核对次数和时间。故障任务因此在多次启动后反复阻塞第一轮轮询。

新版拆分了页面访问与持久化异常。查找某个顾客失败时，记录局部核对失败；页面健康时继续接待其他顾客。数据库写入失败、登录失效、验证码、风控或实际浏览器不可用仍按其真实原因停止提交或进入恢复。

## 本次实现

1. 每次只读核对先保存检查记录并消费次数，再访问页面。核对中进程退出也不会把次数恢复为零。
2. 每条发送最多自动核对两次，每轮最多处理一条。失败安排下次时间；第二次失败结束自动核对并保留人工处理。正常待回复任务先推进。
3. 启动时检查提交时间与证据。超过 90 秒、证据缺失/损坏、会话标识不一致、时区缺失或时钟异常的任务不再反复访问历史会话。
4. 对本次远端数据库中的旧故障任务，停止其过期自动核对安排，保留 uncertain 状态、原始发送记录、异常和人工锁。不会把它改成已发送，也不会再次自动提交。
5. 活动会话标识改为一次 DOM 快照读取；按稳定标识匹配和点击同一行，减少虚拟列表重排后使用旧 index/nth 选错行的风险。
6. 查找会话保留每个目标的扫描进度，单次限制约 3 秒/12 个位置；失败后恢复原列表滚动位置。预算用完只说明本轮没有定位到，不认定会话已删除。
7. 会话切换需要连续两次稳定身份确认。发送后身份短时不一致时，只在原有回读预算内继续观察，不重新点击发送，不放宽身份检查。
8. 普通回复与固定追问在已确认发送后的页面快照失败也与数据库失败分开处理，避免同类误暂停。浏览器恢复或发送通道冷却后，本轮剩余任务停止访问页面。
9. 启动健康检查保留具体状态和原因。新增 `cs_send_checks`，每次核对记录阶段、次数、结果、异常堆栈以及脱敏的期望/实际会话引用，并导出 `send_checks.jsonl`。
10. 提交后保存回读意图失败明确归入持久化故障，停止新增发送。无效提交证据不会导致整个质检 ZIP 导出失败。

## 可能情况与处理

| 情况 | 新版处理 |
| --- | --- |
| 会话在屏幕外、虚拟列表暂未挂载、列表位置变化 | 有限搜索并保留进度；核对失败只影响该顾客，继续其他回复 |
| 列表在读取与点击之间重新排序 | 在同一 DOM 操作中按稳定 ID 校验并点击；之后再确认活动身份 |
| 发送后的 React 状态短时不同步 | 仅在有限回读窗口内观察；持续不一致则保留 uncertain，不重复点击 |
| 会话真的已删除，或旧标识无法再定位 | 最多两次只读核对；之后保留人工处理，不让任务无限占据队首 |
| 核对过程中程序退出或电脑断电 | 次数与备用安排在 DOM 操作前已写入；重启标记上一检查中断，证据过期转人工 |
| 用户数小时后重新启动 | 旧证据窗口过期后停止自动核对，历史发送和人工状态保留 |
| 核对记录缺时间、缺基线、JSON 无效、时间超前 | 标注具体证据问题并停止自动核对；不会据此认定消息未发出 |
| 同文商家消息出现，但应用来源不足以确认 | 保留来源待确认及人工核对，不自动认领、不自动重发 |
| 顾客在核对时发来新消息 | 不补发旧草稿；身份/消息证据不能满足时保留人工核对，未受影响的顾客继续处理 |
| 用户主动接管、售后、发货后业务锁同时存在 | 确认发送仅处理与该发送关联的技术锁，不解除其他仍有效的锁 |
| 浏览器断连、客服页关闭 | 进入现有有限恢复机制；新提交停止，旧发送不再次点击 |
| 验证码、登录失效、风控 | 记录真实状态并暂停，等待用户处理 |
| 数据库锁定、磁盘写入失败或恢复凭据写入失败 | 明确持久化原因，停止新增发送，避免无记录或重复提交 |

上述页面行为是需要防护的可能情况。原始 07:42:43 会话身份不一致的具体页面变化仍无法由现有材料单独确定；直接导致后续全局暂停的异常分类与任务收尾缺陷已修复。
