# 卖家主页工作流架构

## 目标

这个版本只解决一条明确流程：用户提供一个有授权的闲鱼卖家主页链接，选择采集数量，查看商品并下载图片，随后逐件预填到发布页。程序永远不点击最终“发布”按钮。

```text
卖家主页 URL
  → 本机已登录 Chrome/Edge（CDP + Playwright）
  → 有上限的主页滚动与商品链接发现
  → 逐件详情采集
  → 本地商品会话和图片文件
  → 商品审核
  → 发布页预填（人工确认发布）
```

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `ui/SellerSourcePanel` | 输入卖家主页、设置 1–100 件采集上限、显示导入状态。 |
| `crawler/XianyuCrawler` | 验证主页 URL、在动态主页发现商品链接、读取每个商品详情。 |
| `browser` | 启动或复用仅监听本机的 Chrome/Edge CDP 浏览器，维持用户自行登录的会话。 |
| `persistence/SqliteRepository` | 仅作为本地会话缓存，保存商品、图片路径、属性和类目；不再在界面中展示任务管理。 |
| `images/ImageManager` | 下载详情图并将本地路径回写到会话缓存。 |
| `publishing/XianyuPublisher` | 上传已下载图片、预填描述和价格；只在选项唯一且精确匹配时填属性。 |
| `debug/DebugArtifactWriter` | 默认写入图片选择、类目 ID/路径和属性匹配结果，便于页面变动后排查。 |

## 必须保留 Playwright 的原因

闲鱼主页和详情页的直接 HTTP 响应是登录/应用壳，商品列表、详情图和类目数据在浏览器执行页面脚本后才出现。类目 ID 来自详情页响应，属性精确匹配和本地文件上传也必须操作登录后的发布页 DOM。因此 Playwright 是这条小流程的浏览器适配层，不是额外的业务复杂度。

## SQLite 中保留的数据

- 当前或历史导入的内部记录；它是可恢复缓存，不是用户要管理的“任务”。
- 商品正文、价格、详情 URL、多图 URL 与已下载图片路径。
- 类目路径和类目 ID。
- 详情属性及其顺序。

## 明确不在范围内

- 关键词搜索、关键词批量任务、暂停/恢复和任务列表。
- Excel 导出入口。
- 自动提交最终发布、批量自动发布。
- 通过逆向内部 HTTP 接口绕过浏览器页面。

## 安全与使用边界

只能处理用户本人拥有或已获明确许可的卖家主页内容。发布前必须由用户复核图片、描述、价格、类目和属性，并由用户手动完成最终发布。
