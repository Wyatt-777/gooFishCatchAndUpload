## 2. 当前产品目标

应用是 Windows 本地 PyQt6 桌面工具，目前包含两条业务线：

1. 经授权的闲鱼卖家主页商品采集、图片下载、Excel 导出与发布页预填；
2. 闲鱼客服接待：读取聊天、检索本地知识、调用 DeepSeek 生成卖家口吻回复、人工审核或全自动发送，并在安全条件满足时处理待付款订单改价。

重要边界：

- 商品发布只做预填，不点击闲鱼最终发布；
- 客服默认为人工审核模式；
- 全自动模式每次启动前都要求操作员确认，会自动发送文本，也会执行通过全部本地规则的单件订单改价；
- 安全、售后、纠纷、动态物流、媒体消息和无法确定的事实单独转人工，不停止其他顾客的接待；
- API Key 只存 Windows 系统凭据存储，不写入数据库或日志。

### 蓝牙模块现行规则

历史上的“蓝牙加 40 元”已经废止。当前规则是：

- 每款商品都可以加装蓝牙模块；
- 蓝牙由顾客自行选择，不默认加装；
- 未选择蓝牙时使用基础价格；
- 顾客明确选择蓝牙后，标价、议价区间和最终订单改价金额都在基础金额上增加 20 元；
- 单纯询问蓝牙价格不会视为已选装；
- 支持“蓝牙多少钱 → 要”等短上下文确认；
- 顾客说“不用蓝牙了”等取消表达后恢复基础价格。

## 4. 客服回复和议价逻辑

客服循环默认配置：

- 每 2 秒轮询一次；
- 同一顾客连续消息等待 3 秒静默后合并；
- 每轮最多处理 10 个会话；
- 正常情况下，顾客停止输入后约 4-6 秒开始调用模型；
- 发送前重新读取会话；如顾客出现新消息，旧草稿自动失效；
- 使用批次指纹避免重复回复。

回复事实优先级：

1. 当前启用的商品资料；
2. `current-*` 且 `user_curated` 的当前人工确认问答；
3. 历史聊天只用于学习商家语言风格，不可覆盖当前价格、商品或经营事实。

卖家语言风格已经从可靠电池聊天中离线分析并固化：短句、直接、口语化、先给结论、只答当前问题、缺信息只追问一个关键点，不使用“您好/亲/感谢咨询”等客服腔，不机械重复近期回复。

议价由本地确定性规则先做金额判断，模型只负责组织卖家口吻：

- 顾客报价位于最低成交价与标价之间时接受；
- 首次低于底价时使用配置的首次还价；
- 后续顾客提高报价但仍低于底价时可收敛到底价；
- 多件报价不明确时追问是单价还是总价；
- 多件真实订单改价强制转人工；
- 最近四条商家回复会参与去重，模型连续生成相同议价话术时会重试或使用本地安全话术。

## 5. 订单改价现状

入口只允许使用聊天页右上角商品栏中的“修改价格”，不能点击消息气泡里的同名按钮。

当前兼容两种闲鱼改价弹窗：

1. 单金额框：只填写商品价格；
2. 双金额框：第一个框填写商品价格，运费框强制填写 0。

两种情况都存在二次确认：

1. 外层“修改宝贝价格”点击“确定修改”；
2. 出现“您确定要修改价格吗？”浮层；
3. 再点击黄色“确定”；
4. 只有确认提示和外层弹窗都消失才视为成功。

安全约束：

- 只处理顾客明确表示已拍、待付款或要求改价的单件订单；
- 必须已确认唯一型号和唯一成交价；
- 金额必须位于对应商品最低成交价与标价之间；
- 蓝牙选装订单使用含蓝牙价格区间；
- 蓝牙改价任务会保存 `price_adjustment_key` 和 `price_adjustment_amount` 快照；
- 执行前重新确认顾客仍选择蓝牙且当前加价仍为 20 元；
- 页面节点不唯一、金额回读不一致、按钮不可用时不提交；
- 最终提交结果不明确时标记失败，禁止自动重试，交由人工核对；
- 改价失败记录可在界面中手动删除，删除只影响本地审计记录，不操作闲鱼订单。

## 6. 转人工行为

当前通知方式为程序内列表提醒，外部通知渠道仍待定。

转人工后：

- 只暂停该顾客的自动回复；
- 转人工事件持久化并去重；
- 其他顾客继续正常检测和回复；
- 操作员点击“已处理，恢复该顾客”后才恢复该会话。
