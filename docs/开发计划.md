# V1 开发计划

## 总体原则

- 按 Codex 开发指南分阶段交付；每个阶段先说明设计、涉及文件、实现步骤和验收方式，再进入编码。
- 以“采集稳定、人工确认发布、可恢复任务”为优先级，不在 V1 引入 AI、批量发布、多账号或云端服务。
- 所有浏览器动作都必须具备超时、重试边界、日志与对页面变化的可诊断错误信息。

## 里程碑

| 阶段 | 目标与主要产物 | 依赖决策 | 验收标准 |
| --- | --- | --- | --- |
| Phase 1：项目初始化 | Python 项目、PyQt6 空白窗口、统一依赖配置、开发文档。 | Python 3.12 环境 | 执行 `xianyu-assistant` 可打开空白窗口。**已完成** |
| Phase 2：桌面 UI | 主窗口、关键词输入、任务列表、商品列表、设置页的静态交互。 | 确定状态机基本显示规则 | 用户可创建本地草稿任务并操作界面。**已完成** |
| Phase 3：浏览器自动化 | Browser Manager、CDP 本机连接、登录提示、打开闲鱼。 | D-01、D-02 | 用户可自行登录，应用可在不保存密码的前提下打开目标页面。**已完成：Chrome CDP 真实连接验收通过** |
| Phase 4：商品采集 | SQLite 迁移、任务状态机、关键词搜索、商品抽取、过滤、去重与恢复。 | D-04、D-05、D-06 | 采集任务可暂停/恢复，商品数据可落库并在界面显示。**已完成：真实 Chrome/CDP 验收通过（30 条采集、去重与 SQLite 落库一致）** |
| Phase 5：图片和 Excel | 图片下载、目录管理、失败重试、Excel 导出。 | D-05 | 生成包含字段和图片路径的 `output/products.xlsx`，图片目录结构正确。**已完成** |
| Phase 6：发布辅助 | 商品编辑确认、发布页面预填、图片上传、最终人工确认拦截。 | D-06、D-07、D-08 | **本地实现与自动化验收通过；待真实发布页字段适配验证。**程序不会点击最终发布按钮，用户可检查并手动确认。 |
| Phase 7：打包交付 | PyInstaller 配置、干净 Windows 环境测试、日志/数据目录、用户说明。 | 授权实现范围 | 生成并验证 `XianyuAssistant.exe`。 |

## 近期执行顺序

1. 使用真实 Chrome 或 Edge 完成 Phase 3 的 CDP 连接验收。
2. 确认 D-03 至 D-06 的产品决策，尤其是离线授权、暂停恢复和多图模型。
3. 评审平台规则、失败恢复策略和测试账号方案。
4. 开始 Phase 4 的商品采集；不填充发布页。

## 风险控制

- 将站点选择器集中在适配层，避免页面调整时扩散修改。
- 将浏览器命令和数据库操作放入后台工作线程，UI 线程只负责显示与交互。
- 本地数据、图片和日志设置明确的用户可见目录与清理入口。
- 采集频率、重试次数和并发度必须可配置，并采用保守默认值。
